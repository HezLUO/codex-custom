# 公开候选审查

本仓库是从允许的源码文件重新整理的独立本地项目，未导入旧 Git 历史。已在 HezLUO 下创建私有 GitHub 仓库 codex-custom，用于任务管理；本地未配置远程，源码尚未推送，未公开发布。发布前仍需审定 Apache-2.0 许可方案。

已确定默认提供一条终端命令下载安装预编译版本，源码构建作为可选方式。首版范围为已验证的 macOS Apple Silicon 及明确匹配的官方 CLI 版本；不匹配时明确提示兼容范围及官方恢复入口，不自动转入本地编译。该流程已实现，包括严格版本下载、本地安装、离线启动、匹配更新与安全卸载；显式开发者入口仍保留源码构建。决定依据见[安装方式决定](adr/0001-precompiled-installation.md)。

## 纳入内容

- 启动器、更新器、版本化 Rust 补丁。
- 安装/卸载入口脚本、更新器及入口回归测试。
- README、维护与验证说明、LICENSE、上游 NOTICE。
- 隐私审计脚本和最小 .gitignore。

## 已排除内容

旧历史、私有交接文档、原始研究/审查材料、原始验收证据 JSON、截图、终端转录、日志、会话及账户资料、运行目录符号链接、工具链、源码缓存与所有二进制均未迁入。

已确认的发布隐私边界：原始聊天、截图、日志、交接文档、账户信息、会话记录和本机路径均不公开；需要说明功能或验证结果时，使用重新编写的说明与脱敏示例。由项目发起者维护项目，与公开这些私人材料是两个独立事项。

首个公开候选提交使用通用贡献者身份 `Codex Custom contributors <contributors@example.invalid>`，不继承机器全局作者姓名/邮箱；该地址仅作隐私占位，不作为联系渠道。未来真实贡献者可审定使用公开身份，届时相应调整审计脚本的身份规则。

## 可重复审计

```sh
# 修改内容后先暂存明确要公开的文件，再检查
python3 scripts/audit-release.py
# 从一个具体提交导出候选源码（归档目录位于仓库外）
git archive --format=tar HEAD > ../codex-custom-source-candidate.tar
```

脚本核对 index 与工作文件一致、精确文件允许清单、可执行文件模式、未跟踪文件，以及所有本地 refs 可达的 Git 对象。它扫描文件内容、commit/tag 消息和作者字段，检查私人 home/临时目录、常见凭据模式、私钥和会话 UUID。报告只显示规则与对象编号，不打印匹配内容。Git 子树检查以 commit 根路径为准。源码归档可在空目录解包后复核。

该检查属于发布前防误带检查，不能证明不存在所有类型的秘密。发布包以审查过的 Git 提交导出，不上传整个本机目录或 .git 目录；忽略文件、Git 配置、reflog、不可达对象和本机缓存不属于归档内容。不要把私有材料复制进本项目再依赖 .gitignore 隐藏。

## 发布前仍需完成

- 审定许可和公开提交身份；完成公开发布审查后，再取得源码推送及转公开的授权。
- 复核已完成的本地下载、安装、匹配更新与卸载证据，并在公开前确认最终候选摘要与源码提交一致。
- 本地二进制路径清理、溯源、逐成员摘要、ad hoc 签名与依赖通知已完成；四个 MIT 依赖文本缺失仍需维护者在公开前审定。没有开发者身份签名或公证。不直接上传现有安装目录。
- 审查 VALIDATION.md 的实测范围。单纯整理源码位置无需重复完整 Rust 构建；预编译发行验证与尚未实测的真实新版升级流程应分别记录。

公开仓库不应包含机器专属路径、作者私密信息、用户账户数据或原始诊断材料。遇到可能敏感的检查结果，先本地修正，再重新审计整个拟发布历史。

本地候选与验收结果见 [验证记录](VALIDATION.md) 和 [产物格式](PRECOMPILED-FORMAT.md)。候选包含经过等长路径清理并重新签名的既有前端副本，未重跑完整 Rust 构建；实际下载与生命周期验收使用隔离目录及本地 HTTP 服务。候选归档、原始报告、会话夹具和截图均留在仓库外。源码扫描、二进制模式扫描和真实交互验收各自覆盖不同边界，不代表绝对没有隐私问题或全部许可已审清。
